# SYNC-LOG.md

Tracks upstream syncs of the project-local pstack in `.opencode/`.
Source of truth: https://github.com/backnotprop/pstack (standalone mirror of `cursor/plugins/pstack`).
The OpenCode V2 adaptation follows the one in the PlaywrightDotNet repo, minus that repo's own packs (dotnet, testing, UI, graphify, ECC).
Future syncs are manual three-way merges against the mirror, not clean pulls, because this tree rewrites Cursor names for OpenCode.

## 2026-11-11 — lean skill: tiered routing, one owner per concern

- `skills/working-lean-with-poteto/SKILL.md` (local skill): sizes each task (T0 trivial to T3 large, plus Plan) and loads gates only at the step and tier that need them. Each concern has one owner across pstack, superpowers, and ponytail: superpowers owns tests, unknown-cause debugging, done claims, and plans; pstack owns routing, fan-out, and review; ponytail owns diff size. It no longer loads the `ponytail` skill, because the plugin already injects the `full` ruleset every turn, subagents included. `poteto-agent` is kept for T3 code slices; it reads `poteto-mode` (about 9k tokens) before working.
- Baseline before the change: a Muse Spark routing dry run of `/poteto-mode lean` on a one-file guard loaded 6 skills, about 13.4k tokens.
- `docs/harness/opencode.md`: superpowers' startup text says OpenCode v2 has no todo tool; the adapter now says that is outdated here and to use `todowrite`.
- `commands/poteto-mode.md` (hand-edited; the generator no longer owns it): it checks for a chore first (servers, kills, builds, git sync, formatting, package upgrades, PR or CI status). A chore loads no skill and goes to one `general` subagent on the `chores:` model. Anything else loads `poteto-mode`, plus `working-lean-with-poteto` when the request says `lean` or `yagni`. Before this, `/poteto-mode lean` ran the full ceremony for chores, and loading the lean skill depended on the model noticing it.
- Correction to the port entry below: foreground `subagent` calls in one turn run concurrently, not one at a time. A probe on 2.2.7 issued three 15-second foreground workers in one parent message; they started within 41 ms of each other and finished together. The adapter, poteto-mode's Harness, `working-lean-with-poteto`, and `AGENTS.md` now use foreground same-turn calls for fan-out the parent waits on (one wake), and `background: true` only when the parent has other work meanwhile. Two T2 runs under the background rule took 20–25 parent steps, waking once per notice.
- `skills/working-lean-with-poteto/SKILL.md`: an investigation recipe (list directories, one `explore` per area in one turn, answer from the reports). Both T2 runs under the earlier rule read 6–10 files themselves before fanning out over the same areas. With the recipe, 3 of 3 runs did no source scouting and cached reads fell from 880–944k to 200–334k.
- Same skill: when the `how explainer` model is the parent's own model, the parent writes `how`'s sections itself instead of spawning the explainer. In 2 of 3 recipe runs, `how` spawned a Muse Spark explainer under a Muse Spark parent, which re-read the three reports; those runs cost $0.0087–0.0111, against $0.0062 for the run without one.
- Stress matrix of 18 runs on a Muse Spark parent, through the real `/poteto-mode` command endpoint: 9/9 chores went light to `opencode/beam-free#max` (about $0.002 each); 3/3 T2 runs followed the recipe (about $0.006 each); the boundary case (upgrade plus code fix) got the ceremony. Two failures led to two fixes in the same skill. A T1 run loaded `writing-plans` because the prompt asked for a plan, so `writing-plans` now applies only to a multi-task plan saved to a file. A T3 design was sized T2 by file count, so a design deliverable is now T3 whatever its file count. In two full T3 design runs, the parent collapsed the multi-model design step into itself: one ran a "two candidate bakeoff inline", the other matched the Prototype playbook and skipped `architect`. T3 now requires `architect` for any design deliverable, with its runners as subagents on their role lines. After that change, 1 of 2 runs spawned a DeepSeek and a Muse Spark runner in one turn; the other still "compared inline … per your lean no implementation order". The rule is now a numbered design recipe in which runners are a required step, and it states that a prototype or no-implementation request still runs them, because runners only sketch.
- `pstack-models.md`: `chores` is now a real role line (`opencode/beam-free#max`), not a comment; in testing, the comment form was skipped in 2 of 5 chores. `skills/setup-pstack/SKILL.md` lists `chores` as a local role so a rerun keeps it.

## 2026-11-11 — OpenCode V2 port, mirror 0854796 (0.15.36)

- Mirror `backnotprop/pstack` @ `08547969e1dffaa6457ea65141cc62c1d9a2eef1`. Since the last adapted sync (`a6342de`), upstream changed only `SYNC-LOG.md` and sponsor SVGs. The vendored skills and agents equaled the mirror byte for byte before this port.
- `agents/poteto-agent.md`, `agents/comment-sicko.md`: added `mode: subagent` and dropped `name` and `is_background`, which V2 ignores. Before this, both resolved as `primary` agents, and V2 refuses to spawn a primary agent ("cannot run as a subagent"). `poteto-agent` now reads `.opencode/skills/poteto-mode/SKILL.md` instead of searching `~/.cursor/plugins/`. `comment-sicko` gains a harness note: it runs `/how` and `/why` itself, because a subagent cannot spawn subagents.
- `skills/reflect/references/*-reviewer.md`: a skill now counts as used after a `read` under `.opencode/skills/` or a `subagent` prompt naming its path.
- Skills rewritten for V2 names (`subagent` tool with `agent`, `.opencode/pstack-models.md`, `.opencode/skills/`, `opencode session list`/`export`): architect, arena, automate-me, create-verification-skill, how, maintain-verification-skill, no-comments, poteto-help, poteto-mode, recall, reflect, setup-pstack, swarm, why. `statechart/scripts/package.json` renamed to `@pstack/statechart`. The PlaywrightDotNet graphify seeding in `how` and `why` was not carried over.
- `skills/poteto-mode/SKILL.md` Harness: parallel fan-out uses `background: true` on every worker in one turn; role lines are explicit model choices; `/loop` maps to the built-in `/goal` and to `schedule_create`; verification uses `dotnet test` plus Playwright or a CDP browser.
- `docs/harness/opencode.md`: the Cursor-to-OpenCode adapter. Verified on 2.2.7 against the installed binary: subagent params (`agent`, `description`, `prompt`, `model`, `background`, `sessionID`), the primary-agent refusal, the depth limit of 1, and the `experimental.todo` and `experimental.schedules` gates.
- `docs/guide/`, `docs/harness/claude-code.md`, `README.md`: upstream docs. The README's benny automation paragraph is replaced with an OpenCode note.
- `skills/deslop/`: vendored from `cursor/plugins` `cursor-team-kit` 1.2.0 (MIT) @ `5866df5`, byte-identical. poteto-mode and `working-lean-with-poteto` gate commits on it.
- `commands/`: one wrapper per non-`principle-*` skill plus `deslop` (35), generated from each skill's `description`. V2 does not expose skills as slash commands, so before this `/poteto-mode`, `/swarm`, and the rest did not exist here.
- `pstack-models.md`: per-role models as exact `provider/model#variant` IDs from the `opencode` and `opencode-go` providers, verified with `opencode models` and `opencode api GET /api/model`.
- `opencode.json`: `experimental.todo` (enables `todowrite`), `experimental.schedules` (enables `schedule_*`), and `instructions` loading `pstack-models.md`.
- `skills/working-lean-with-poteto/SKILL.md` (local skill, not upstream): short model names replaced with exact IDs, the `subagent` spawn and background fan-out spelled out, and `ponytail` named as a plugin skill.
