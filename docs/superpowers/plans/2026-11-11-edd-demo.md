# EDD Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Single-container event-driven demo (2 producers, 2 consumers, 1 command API, 1 React dashboard, Kafka as only channel) under `src/backend` + `src/frontend`, built and run via one Dockerfile.

**Architecture:** DDD layers (`EventDrivenDesign.Domain` → `.Application` → `.Persistence` / `.Infrastructure`, shared kernel `.Shared`, wire contracts `.Contracts`, transport `.Messaging`); pure microservices, one solution per deployable plus a root solution; pure C# in-process dispatch (abstract-record unions + exhaustive `switch`, `IMessageHandler<T>`); Kafka topics per game-plan; SQLite WAL sinks; transactional outbox on producers + idempotent sinks on consumers; ASP.NET controllers (no minimal APIs); React polls REST 1 s.

**Tech Stack:** .NET 11.0.100 / C# 15 (`mcr.microsoft.com/dotnet/sdk:11.0` verified on MCR; local SDK install in progress, abstract records until then); `Confluent.Kafka`, `Microsoft.Data.Sqlite`; React + Vite + TypeScript + Tailwind (bun, not node); nginx; Kafka 4.4 KRaft; supervisord; xUnit.net v3.

**Spec:** `docs/00-edd-demo-game-plan.md` (decisions, contracts, diagrams, phases 0–5, demo script). This plan argues from that spec; executors read both.

## Global Constraints

- Layout: `src/backend/*` dotnet only, `src/frontend` react only (user override of spec `src/Edd.*` + `web/`).
- API style: controllers only, no minimal APIs; `Program.cs` uses explicit `Main` + block namespaces (user override of spec minimal API).
- Transport: http only, no https redirection in container.
- Frontend tool: `bun`, never npm/node.
- Docker: one image, cached layers, small/fast; no VOLUME (user override — data ephemeral, `shortcut: add named volume when persistence matters`).
- .NET: `net11.0`, Nullable enable, `TreatWarningsAsErrors=true`, 100% XML documentation (`GenerateDocumentationFile`, `NoWarn` must NOT silence 1591).
- Central package management: `Directory.Packages.props` only, no floating versions.
- Solution name: `EventDrivenDesign`. Layers: `EventDrivenDesign.Domain`, `.Application`, `.Persistence`, `.Infrastructure`, `.Shared`, plus `.Contracts`, `.Messaging` (correct spelling: Persistence/Infrastructure).
- Pure microservices, separate solutions: root `EventDrivenDesign.slnx` (everything, container build) + per-deployable `src/backend/EventDrivenDesign.{Api,Producer,Consumer}.slnx`, each referencing only the lib projects it needs.
- Shared logic lives in libs only; hosts reference libs, never each other.
- Delivery guarantees: producers use transactional outbox (SQLite outbox table + relay publishes to Kafka); consumers are idempotent sinks (`INSERT OR IGNORE` on `event_id`, DB commit before offset commit); producers use idempotent Kafka producer (`acks=all`).
- Only required external deps: `Confluent.Kafka`, `Microsoft.Data.Sqlite` (+ test: `xunit.v3`, Playwright only in Task 6).
- Cross-cutting: Options pattern (`IOptions<T>` + validation), Result pattern (no exceptions for expected failures), structured logging (source-gen `LoggerMessage`), global exception handling (middleware → ProblemDetails).
- Pure event-driven: no service calls another service; commands/acks/heartbeats/events ride Kafka; only React→API REST and API→DB read-only files break the rule.
- TDD every task: failing test first, watched fail, minimal green, full suite before commit.

## Review Focus

- Producer restart replays compacted command and restarts idle/finished run — expected: stays Idle, test in Task 3.
- SQLite WAL on container overlay without volume under memory pressure — expected: `busy_timeout`, single writer, no `SQLITE_BUSY` surfacing, test in Task 2.
- `SetRate` for non-Running producer — expected: 409 Conflict, never compacted, test in Task 3.
- Malformed Kafka record — expected: DLQ + offset stored + loop continues, test in Task 2.
- Dashboard on 360px wide phone with broker down — expected: tiles show Down, no layout break, controls disabled, test in Task 5.
